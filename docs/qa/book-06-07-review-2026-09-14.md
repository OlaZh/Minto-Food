# BOOK-06 / BOOK-07 — перегляд достовірності QA

Дата: 14.09.2026. Переглянув: Codex. Поточний статус обох пунктів: **PARTIAL**, чекбокси відкриті.

Це перегляд скриптів і попереднього звіту від 08.09.2026, а не новий браузерний прогін. Числа **18/18** і **13/13** збережено як заявлені результати попереднього запуску. Вони не доводять повний PASS відповідних сценаріїв.

| Пункт | Що охоплює наявний скрипт | Що залишається неперевіреним |
|---|---|---|
| BOOK-06 | Вручну вставлена спрощена модалка; 30 тестових кнопок; геометрія/перекриття останньої; завершення click; власний скрол сітки та wheel. Лише світла тема, Chrome, три viewport: 1440×900, 390×844, 1280×600 | Відкриття та повна розмітка реальної модалки; робота renderer; вибір і збереження обкладинки; блокування фонового скролу при wheel/touch, включно з межею сітки; темна тема й touch-поведінка |
| BOOK-07 | 6 regex-перевірок live-файлу та 7 перевірок штучного DOM/виклику signOut у гостя. Після виклику перевіряються книги, optional recent, edit-вузол, тестові маркери та aria-busy | Logout справжньої сесії, відкриті book/edit-модалки, затримані відповіді завантажувачів, перехід користувач A → logout → B і відсутність повернення даних A |

У BOOK-06 не викликаються `createEditBookModal()` та `renderCoverGridHTML()`. Копія розмітки не містить «Без фото», заголовків серій, default-поля та обробника вибору. Успішний `click()` підтверджує доступність кнопки, але не зміну обкладинки. Скрипт примусово скидає блокування скролу `body`; `window.scrollY` порівнює лише до/після присвоєння `grid.scrollTop`. Під час wheel фоновий скрол не вимірюється.

У BOOK-07 немає активної авторизованої сесії. Edit-вузол вставляється без active-класу, а дані відкритої книги не наповнюються. Seed не вимагає наявності двох recent-записів; assertion після виклику допускає відсутній recent-контейнер. `signOut()` викликається, але повернене поле `error` і фактичне отримання події `SIGNED_OUT` окремо не перевіряються. Збіги regex підтверджують наявність тексту, а не коректність guards у гонці запитів.

Під час перегляду запуск із репозиторію завершився `ERR_MODULE_NOT_FOUND` для `playwright-core`; попередні браузерні результати незалежно не відтворені. Скриншоти `book06-{1440x900,390x844,1280x600}.png` та `book07-after-logout.png`, згадані раніше, у репозиторії не знайдені. Новий PASS, нові скриншоти чи прив'язку до поточного deployment цей перегляд не засвідчує.

## Виправлена інструкція запуску

`playwright-core` не є залежністю проєкту. Root `package-lock.json` і Sass уже є; AUTO-07 має PASS від 08.09.2026. Для окремого запуску потрібно скопіювати скрипти поряд із scratch-залежністю: зміна поточної директорії не змінює резолвінг bare import у файлі з репозиторію.

PowerShell, із кореня репозиторію, за наявності Node/npm, мережі та системного Chrome за шляхом у скриптах:

```powershell
$bookQaDir = Join-Path $env:TEMP 'minto-book-qa'
New-Item -ItemType Directory -Force -Path $bookQaDir | Out-Null
Copy-Item -LiteralPath 'scripts/book-06-cover-scroll-check.mjs', 'scripts/book-07-logout-cleanup-check.mjs' -Destination $bookQaDir
Push-Location $bookQaDir
try {
    npm.cmd init -y
    npm.cmd install playwright-core
    node ./book-06-cover-scroll-check.mjs
    node ./book-07-logout-cleanup-check.mjs
} finally {
    Pop-Location
}
```

Цю виправлену інструкцію під час перегляду не виконували. Скрипти звертаються до `https://minto-food.vercel.app`; скриншоти створюються в scratch-каталозі. Навіть якщо всі їхні assertions пройдуть, покриття пунктів залишається PARTIAL до перевірки сценаріїв у таблиці. Console errors виводяться, але не впливають на підсумковий код завершення.

## Уточнення для наступної QA

- Гостю достатньо валідного `minto_consent` з поточною `version` і `savedAt` у межах TTL; `minto_consent_seen` не є обов'язковим другим ключем. Це випливає з `getConsent()` і гостьової гілки ініціалізації в `js/cookie-consent.js`.
- ID модалки входу — `auth-modal`. Видалення її з DOM і скидання body lock є обходом лише для ізольованого тесту, не підтвердженням користувацького сценарію.
- PROFILE-08 виправлено й перевірено локально 08.09.2026; deployment/live-регрес не підтверджені.
- З чотирьох обговорюваних фіксів відкриті BOOK-06, BOOK-07, ADM-08 і MOD-01. Усі інші відкриті пункти фази 22 залишаються в [QA-плані](../qa-test-plan.md) та [Roadmap v2](../Roadmap_v2.md).
