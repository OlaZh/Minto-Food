# Переклади інгредієнтів рецепта

У редакторі одного рецепта інгредієнти мають вкладки UA / EN / PL.
Кожна вкладка зберігає повний текст, включно із заголовками розділів,
кількістю, одиницями та примітками. `ingredients` залишається оригінальним
українським текстом; `ingredients_en` і `ingredients_pl` — окремі переклади
в тому самому рядку `recipes`. Порожнє поле очищає відповідний переклад.

Список продуктів `product_recipe` і розрахунок КБЖУ спільні для всіх мов.
Переклади тексту не створюють додаткових рецептів або списків продуктів.
Кнопка «Розпізнати» на вкладці UA зберігає текст із заголовками й примітками;
як і раніше, вона додає розпізнані продукти до поточного списку.

Сайт і перегляд із кулінарної книги вибирають інгредієнти та кроки відповідно
до мови інтерфейсу. Якщо переклад ще порожній, використовують український
текст. Для рецептів без текстового списку залишається показ продуктів
із довідника з їхніми перекладеними назвами.

## Порядок застосування

1. Виконати в Supabase SQL Editor перевірку
   `supabase/preflight/20261004_recipe_ingredient_translations_preflight.sql`.
   Вона працює у read-only транзакції. `READY_TO_APPLY` означає, що можна
   додати колонки; `ALREADY_PRESENT` — обидві вже існують у потрібному
   форматі. За будь-якого `STOP_*` спочатку переглянути причину.
2. Виконати в Supabase SQL Editor
   `supabase/migrations/20261004_1000_recipe_ingredient_translations.sql`.
   Міграція додає дві nullable text-колонки та оновлює кеш REST-схеми;
   існуючі рецепти, зв'язки продуктів і права доступу не змінюються.
3. Опублікувати зміни адмінки та основного сайту.
4. В одному рецепті заповнити три тексти, зберегти й повторно відкрити.
   Перевірити перегляд на UA / EN / PL у книзі та на публічній сторінці.

До застосування міграції нові поля недоступні для збереження, а запит
публічної сторінки з новими полями не працюватиме. Самі зміни коду не
застосовують SQL до робочої бази.

Користувач підтвердив виконання міграції 04.10.2026. Перевірка робочого
REST API з `select=ingredients,ingredients_en,ingredients_pl&limit=0`
повернула HTTP 200 та `[]`: усі три поля доступні через API. Адмінка й
основний сайт налаштовані на той самий Supabase-проєкт.

## Перевірки

```powershell
node --no-warnings --test scripts/recipe-translations-check.mjs
```

Перевірка охоплює вибір мови й fallback, завантаження/збереження/повторне
відкриття форми, очищення перекладу, створення рецепта та збереження
спільного списку продуктів. Збереження форми перевіряється зі справжньою
React Hook Form і тестовими серверними діями, без записів у робочу базу.

SQL-тест використовує наявну локальну PGlite, як інші перевірки рецептів.
Якщо вона ще не встановлена:

```powershell
npm.cmd install --prefix node_modules/.cache/recipe-media-qa @electric-sql/pglite@0.5.8
```

## Відкат

Спочатку відкотити код. Файл
`supabase/migrations/20261004_1000_recipe_ingredient_translations_rollback.sql`
відмовляється видаляти колонки, доки вони містять непорожні переклади.
Перед їх явним очищенням потрібно зберегти переклади; для destructive
операцій застосовуються правила `supabase/migrations/README.md`.
